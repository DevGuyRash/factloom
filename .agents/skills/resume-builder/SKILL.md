# Resume builder

For a new batch, start with [research-mode onboarding](references/research-mode.md): proactively explain its enabled synthetic-content defaults and offer the controls and evidence-only choice before drafting. A user need not know the mode's name. Reuse existing batches' saved settings. Clear research/test context permits wholly generated or mixed career content under those controls; clarify ambiguous personal-career use before inventing claims. Evidence-only always disables invention, and genuine career work uses the process below. Keep the same files, commands, and build flow. Provenance, consent, observations, and real-person records remain factual; external testing still requires company agreement and the user's authorization.

This process serves any profession, seniority, employment background, and document type, including concise resumes, long CVs, and project-based records. Derive priorities and depth from the intended use and full context; no occupation, length, or another person’s goals are defaults. Build the strongest supported case at the depth its audience needs. The repository keeps each claim in `people/<person>/resumes/source/facts.yaml`, its source in `evidence.md`, variants selecting facts, themes controlling appearance, and guides explaining targets ([resumes reference](../job-application/references/resumes.md)). For a new person, follow AGENTS.md's private-copy setup first.

## What holds throughout

- Preserve the full usable career record, original sanitized source detail, provenance, uncertainty, and dated user corrections before selecting a resume. Trace material evidence through reusable facts, selection, and final output against its purpose; selected text alone cannot establish source coverage. Research mode preserves meaningful supplied content too, with generated additions or deliberate transformations recorded separately. Templates must carry selected content faithfully.
- Facts come from the person and their authorized records. Research supplies selection criteria, vocabulary, and focused questions; typical duties stay proposed additions until the person's evidence supports them. A title, repository, or prototype alone does not establish duties performed, employment, production use, or results.
- New or changed factual meaning needs source verification and confirmation when not already approved. Preserve prior approval through purely editorial wording, shortening, or reordering that keeps the same factual scope and intended use. Unresolved bullet claims go in `confirm`; unresolved non-bullet claims go in the affected guide's manual `review`. Research changes emphasis and language, not qualifications.
- Read existing records before asking for more. Ask focused, material questions; draft the supported parts while uncertain claims wait. Use `--out` while substantive approval is pending; approved changes can build directly into active with final file review. Resume work leaves application permissions and pauses unchanged. Save coherent changes using the shared [checkpoint policy](../../../AGENTS.md#local-checkpoints-in-consumer-work).

## The work

1. **Understand the context, then frame the document.** Review all existing conversation, records, supplied source versions and sections, and prior decisions before recommending pages or writing. Invite any extra general notes or an unstructured context dump; if none is available, proceed from what is known. Establish the audience and suitable document type. Use context-aware preservation priorities, distinguish must-keeps and hard employer constraints from preferences, and ask only about meaningful unresolved trade-offs ([writing](references/writing.md)). Reuse settled page constraints; otherwise recommend a suitable length and ask only when an unresolved material trade-off needs the person’s choice. A general resume can represent professional breadth without an exact vacancy.
2. **Research the decisions** ([research](references/research.md)). Use the employer's official posting and relevant product, team, or hiring material to distinguish required and preferred responsibilities, fit, and the target argument. Adjacent roles can clarify transferable strengths. Compare these criteria with the person's evidence; employer values establish no candidate belief or experience. Reuse dated sources and stop when more research no longer changes the case, variant boundaries, or material gaps.
3. **Recover missing proof** ([interviewing](references/interviewing.md)). Start with the records, then clarify relevant incidents, personal contribution, scale, users, and results. Record source and uncertainty as you go. Concrete work can be persuasive without metrics; never invent them.
4. **Write distinct variants** ([writing](references/writing.md)). Select the strongest evidence for each genuinely different audience while preserving supported search terms and skills. `./resumes variant new <name> --person <slug> --no-build` creates a guide and structure listing all facts; select and order them for the intended format before rendering. Hold only variants whose selected content or intended use needs unresolved approval, not siblings using unchanged claims. Build with `./resumes build-resumes --person <slug> --variant <name>`; add `--out <review-dir>` while substantive approval is pending. The build's mechanical floor is neither editorial approval nor an ATS guarantee.
5. **Review and revise** ([review](references/review.md)). Have a fresh reader, when available, assess the built resume against the target before seeing the writer's rationale. Review the actual source and output changes against original evidence, purpose, and recorded corrections; inspect each delivered format's text and pages. Correct material defects and check affected content again. Stop when remaining items need specific evidence or are optional preferences.
6. **Deliver and settle.** Give the person the reviewed files, each variant's purpose, material rewordings or omissions and why, and a focused batch of unresolved claims. Keep their theme unless a different layout is useful or requested; offer previews when appearance needs a decision. Update guides from the research rather than repeating it. Preserve review items until resolved.

A draft is deliverable with clearly labeled uncertainties. A variant is sendable when its factual content and intended use are covered by the person's approval, factual and manual review items are resolved, final active files pass review, and `./resumes check` passes (with any accepted mechanical warnings explained). Purely editorial revisions do not revoke that approval. Resume approval does not start applications. Report what was actually built and checked, and any unavailable format or blocked decision.
